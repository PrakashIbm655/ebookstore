eBookstore REST API

Project Transcript — Architecture, Security & Endpoint Reference

1. Project Overview

eBookstore is a production-ready Spring Boot REST API for an online bookstore. It covers the full shopping lifecycle: user registration & login, product catalogue browsing, cart management, address management, payment processing (mock gateway), order history, and a collaborative-filtering recommendation engine.

Java + Spring Boot Spring Security + JWT Spring Data JPA PostgreSQL BCrypt password hashing Swagger / OpenAPI 3 Port 8080 · localhost only
The server binds to 127.0.0.1:8080 only — it is not exposed to all network interfaces, in compliance with security best practices.

3. Authentication & Security

How it works

  • Stateless JWT-based authentication — no sessions, no cookies.
  • Tokens are signed with HMAC-SHA256 using a secret supplied via the JWT_SECRET environment variable (minimum 32 bytes).
  • Default token expiry: 1 hour (configurable via JWT_EXPIRY_MS).
  • Passwords are hashed with BCrypt — never stored in plaintext. BCrypt cap enforced at 72 characters.
  • Emails are normalized (trimmed + lowercased) before storage.
  • Database credentials, JWT secret, and DB URL are all sourced from environment variables — never hardcoded.

Token Usage

Pass the token in the Authorization header for every protected request:

Authorization: Bearer <your_jwt_token>

5. End-to-End User Journey

1
Register or Login Call POST /auth/register or POST /auth/login. Save the token from the response.
2
Browse the Catalogue Call GET /products with optional filters to find books. Use GET /products/{id}/related for recommendations.
3
Save a Delivery Address Call POST /users/me/addresses with your address details. Note the returned address id.
4
Add Items to Cart Call POST /cart/items for each product. Check GET /cart to review your cart and note the cartId.
5
Initiate Payment Call POST /payments/initiate with your cartId, addressId, and method. Optionally redeem gift points. Save the returned paymentId.
6
Confirm Payment Call POST /payments/confirm/{paymentId}. The mock gateway processes the payment and the order is created.
7
View Order History Call GET /orders for history or GET /orders/{id} for detail. Use POST /orders/{id}/reorder to repeat a past order.

6. Error Handling

All errors return a consistent JSON structure via GlobalExceptionHandler:

{ "timestamp": "2026-10-11T04:37:18.417Z", "status": 400, "error": "Bad Request", "message": "Validation failed", "path": "/auth/register", "violations": [ { "field": "password", "message": "size must be between 8 and 72" } ] }
StatusMeaning
400Validation failed / bad request payload
401Missing or invalid JWT token / wrong credentials
404Resource not found (product, order, address, …)
409Conflict — e.g. email already registered
